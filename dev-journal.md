### 2026-06-01 — Built Flask backend + auth endpoints

**Goal for today**
Get the backend running with register and login endpoints.

**What I did**
- Set up Flask project structure with Blueprints
- Connected MongoDB locally
- Built /api/v1/auth/register and /api/v1/auth/login
- Tested both endpoints with Invoke-WebRequest

**What I learned**
- Virtual environments isolate project packages
- Blueprints group related Flask routes together
- Passwords should always be hashed with bcrypt, never stored raw
- JWT tokens are returned on login and used for future requests
- MongoDB needs to be started manually with --dbpath on Windows

**Problems I ran into**
| Problem | What I tried | What fixed it |
|---------|-------------|---------------|
| MongoDB connection refused | net start MongoDB | mongod --dbpath C:\data\db |
| make_classification error | n_informative=4 | changed n_classes=2 |
| bcrypt not found | — | pip install bcrypt |

**Next session**
Test the /api/v1/predict endpoint with a JWT token.

**What I learned**
- A virtual environment isolates packages so different projects don't conflict. 
- Run `python -m venv venv` at shell to create the virtual environment. The first venv means invoking Python's built-in virtual environment module. The second venv is the name I gave to the virtual environment, which can be any variable's name. 
- `venv\Scripts\activate` on Windows vs `source venv/bin/activate` on Mac/Linux
- Run `pip list` to see what packages we have installed. Run ` pip freeze > requirements.text ` to save this list so anyone can recreate our exact envirment. When we put this on GitHub. anyone can run `pip install -r requirements.txt` and get the exact same setup.
- `tree` is a command that visually displays your folder structure as a tree diagram 
- Use `New-Item <filename>` to create a new file
- Register: User sends email + password → check if email exists → hash the password → save to DB → return success
- Login: User sends email + password → find user in DB → check password hash → generate JWT token → return token
- User sends financial data → check they're logged in → validate the data → run ML model → return risk score
- fields.Float — must be a decimal number (like 55000.0)
- required=True — if the frontend doesn't send this, marshmallow throws a ValidationError immediately
- Load model from disk → convert data to DataFrame → get probability scores → get predicted label → return human-readable result
- python run.py
    → create_app() runs
        → Flask app created
        → config loaded
        → MongoDB connected
        → JWT connected
        → routes registered
    → server starts on localhost:5000
    → waiting for requests...
- Train model → lives in RAM → script ends → 💨 gone
- Train model → pickle it → saved as model.pkl → reload anytime ✅
- A quick way to generate a good one — run this in your terminal: python -c "import secrets; print(secrets.token_hex(32))"

## Packages

| Package | What it does | Where you'll use it |
|---------|--------------|---------------------|
| flask | The web framework - handles HTTP requests and routes | Every backend file |
| flask-jwt-extended | Adds login token (JWT) support to Flask | ` routes/auth.py ` |
| flask-pymongo | Connextes Flask to your MongoDB database | ` app/__init__.py ` |
| marshmallow | Validates incoming data from the frontend | `schemas/predict_schema.py` |
| xgboost | ML model for credit risk prediction | `ml/train.py` |
| lightgbm | Alternative ML model = faster than XGBoost on large data | `ml/train.py` |
| pandas | Handles data as tables(DataFrames) | `services/ml_service.py` |
| joblib | Saves and loads your trained model as a .pkl file | `ml/train.py` + `services/ml_service.py` |
| python-dotenv | Reads secret settings from a .env file(like your MongoDB password) | `app/config.py` |
| pytest | Runs your tests automatically | `tests/` folder |
